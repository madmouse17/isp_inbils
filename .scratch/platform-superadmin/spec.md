# Platform superadmin panel (SaaS operator): companies, provisioning, impersonation, support

Status: ready-for-agent
Ledger: `docs/plans/INBILS_OMP_BACKLOG.md` → "ISP roadmap lanes (2026-10-12)" row `platform-superadmin`
Source: owner request 2026-10-14 (grill-me): "buatkan saya halaman superadmin untuk saya mengelola semua data perusahaan yang menggunakan aplikasi saya, dan biar saya bisa membuat akun perusahaan dengan mudah dan bisa melakukan impersonate maupun yang lainnya, buat biar powerfull untuk kebutuhan saya terhadap komplain nantinya". Owner approved SA1–SA8 as recommended and asked for specs/tickets "seperti biasa" (round-2 items decided by the assistant: R1–R8).

## Facts (2026-10-14, agent SuperadminFacts)

- No platform layer: no superadmin role/flag/guard/route, no `Gate::before`, no impersonation package; highest scope is `admin` inside one effective company. Roles/permissions are global (spatie `teams=false`); `RolePolicy::ownsRoleDefinitions` lets any top-level company edit role definitions.
- Company creation: one-shot `/setup` wizard (`RequireNoCompany` 403 once any company exists) promoting the logged-in user; `inbils:company:create-subsidiary` CLI (no admin user); defaults via `SetupWizardService::defaultSettings`, `CompanySeeder::runFor` on `CompanyCreated`.
- `companies.is_active` is honoured by scheduled jobs and company switching, **not** by login or the API: users of a deactivated home company still log in (security gap).
- No company delete flow, no per-company export. Files under `storage/app/private/companies/{id}`.
- Reusable: TOTP 2FA (optional today), `password.confirm`, `AuditService` (activity log; null-company entries are quarantined), `ApiTokenService::revokeAll`, `CompanyService::runAs`/`forCompany`, fail-closed `BelongsToCompany`.
- Design today is one ISP group per install; `users.email` and `companies.code` are globally unique.

## Decisions

- **SA1 SaaS:** one install hosts many unrelated ISPs. A tenant is a top-level company (Head) with its subsidiaries; existing installs become one tenant each.
- **SA2 Separate identity:** table `platform_admins` (name, email unique, password, 2FA columns, is_active, last_login_at), guard `platform` (session driver), login `/platform/login`, routes under `/platform` (R1). Platform admins are never tenant users, never in `company_user`, never assignable by tenants. First platform admin via `php artisan inbils:platform:admin-create` (interactive, like `inbils:setup`).
- **SA3 Impersonation:** a platform admin starts "Masuk sebagai" on a tenant user with a required reason (complaint reference, 5–200 chars); the web session logs in the tenant user with a session marker `impersonator_platform_admin_id`, `impersonation_started_at`, `impersonation_mode`; hard limit 30 minutes; persistent banner "Anda masuk sebagai {nama} ({perusahaan}) · superadmin {nama} · mode {baca|ubah} · sisa {mm:ss} · Keluar". Default **read-only**: middleware rejects every non-GET/HEAD request (except leaving) with 403 and an Indonesian message. **Write mode** is switched on explicitly after `password.confirm` on the platform account; every write is audited with the platform admin as the real actor. Never: impersonate a platform admin, bypass the user's own 2FA settings page, see passwordes/2FA secrets/recovery codes/API tokens, issue API tokens, change the impersonated user's password/email/2FA, or impersonate a user of a suspended company. Mobile apps are out of scope (web only).
- **SA4 Platform account security:** 2FA mandatory (enrol on first login, cannot be disabled), `password.confirm` (platform guard) before impersonation, write mode and dangerous actions, idle timeout 30 minutes, login throttle 5/min per email+IP and 20/hour per email. No IP allowlist in this lane (owner, 2026-10-14: "tidak usah ada dulu untuk allowed ip"); parked in `docs/PARKING_LOT.md`.
- **SA5 Provisioning:** "Perusahaan baru" form: company (name, code, timezone, currency, optional logo) + first admin (name, email). Creates the company through the same services as the wizard (defaults, `CompanySeeder::runFor`, `CompanyCreated`), creates the admin user (random password, `admin` role, membership) and sends the set-password invitation (existing password-reset mail path with an Indonesian "Undangan" mail). Optional checkbox "Isi data contoh" runs the demo seeders for that company only (trial accounts). `/setup` stays for brand-new installs.
- **SA6 Lifecycle:** Tangguhkan (sets `is_active=false`; blocks web login and every request of users whose home or active company belongs to the tenant with "Akun perusahaan ditangguhkan, hubungi dukungan"; revokes all their API tokens; scheduled jobs already skip), Aktifkan kembali, Ajukan hapus (only after 30 days suspended and a completed export; marks `deletion_requested_at`; the purge itself is `php artisan inbils:platform:purge-company {code}` with a typed confirmation, never a web button).
- **SA7 Transparency:** every impersonation (start, mode change, end, each write in write mode) is written to the platform audit log and to the tenant's audit log as "Akses dukungan oleh tim Inbils" with reason and duration; tenant admins see it in Audit Log.
- **SA8 Panel v1:** companies list (status, users, customers, last login, storage used, failed jobs and failed notifications/WhatsApp in 7 days, plan placeholder none); company detail (profile, admins, subsidiaries, recent audit, failed notifications/WhatsApp, failed jobs for that tenant); actions: impersonate, reset a tenant user's 2FA, resend invitation, unlock throttled login (clear limiter keys), suspend/reactivate, request deletion, export data. SaaS billing/plans are out of scope (parked).
- **R1 Path, not subdomain:** `/platform` on the same host; optional `PLATFORM_DOMAIN` env to bind the routes to a host when the owner sets one.
- **R2 Role definitions become platform-owned (closes a cross-tenant hole):** with several unrelated ISPs, global roles edited by any top-level company would let ISP A change ISP B's permissions. Tenants keep assigning the seeded roles to their users; creating/editing/deleting roles and their permissions moves to the platform panel ("Peran & hak akses" page); `RolePolicy` denies role definition writes to every tenant user. Per-company roles (spatie teams) parked as a later lane.
- **R3 Global uniqueness accepted:** `users.email` stays globally unique (one email = one account across ISPs; a person working for two ISPs uses two emails); `companies.code` stays globally unique, but only platform admins create companies now, so tenants never probe codes.
- **R4 Double confirmation** (platform password re-confirm + typing the company code) for: suspend, request deletion, export, write-mode impersonation.
- **R5 Export:** queued job builds a ZIP (one CSV per tenant table via `CompanyService::runAs`, plus the tenant's private media folder), stored on the private disk under `platform/exports/`, downloadable by platform admins for 24 hours via a signed route, then deleted by the scheduler; export audited on both sides.
- **R6 Platform audit log:** `activity_log` with log name `platform`, causer = platform admin (morph), `company_id` = the target tenant when there is one; platform page "Audit platform" with filters.
- **R7 Rule changes recorded:** ADR `docs/architecture/decisions/ADR-003-platform-superadmin.md` (allowlisted in `.gitignore`), amended AGENTS.md "Company Rules" (platform layer is the only web path allowed to read across tenants; it always goes through `runAs`/`forCompany` per tenant; subsidiaries may also be created by platform admins), amended `docs/SECURITY.md` (platform guard, impersonation rules, tenant suspension). Design by `architect`, sign-off by `security-reviewer` (AGENTS.md protocol for auth/permission work).
- **R8 Order:** after `field-trip-status` and before `opaque-ids` (platform routes then get public ids in that lane). The deactivated-company login gap was fixed standalone on 2026-10-14 (CHANGELOG "Deactivated company can no longer log in"); ticket 03 adds the suspend/reactivate actions on top of that enforcement and does not re-implement it.

## Testing decisions

- Guard isolation: tenant session cannot reach `/platform/*`; platform session cannot reach `/admin/*` except through impersonation; 2FA mandatory.
- Impersonation: read-only blocks writes (table-driven over a sample of POST/PUT/DELETE routes), write mode allows and audits with the real actor, 30-minute expiry, forbidden targets (platform admins, suspended tenants), forbidden pages (own password/email/2FA), banner props, tenant audit entry.
- Provisioning: company + admin + defaults + invitation; code/email uniqueness; demo-data option scoped to the new company.
- Suspension: web login and every request of tenant users blocked, API tokens revoked, reactivation restores login.
- Role definitions: tenant admin 403 on role writes; platform admin can edit.
- Export: ZIP contains only that tenant's rows (fixture with two tenants), signed link expiry, cleanup.
- E2E: platform login with 2FA, create company, impersonate read-only (write blocked with message), switch to write mode, leave; suspend → tenant login blocked.
